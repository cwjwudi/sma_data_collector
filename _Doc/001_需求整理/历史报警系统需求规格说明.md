# 历史报警系统需求规格说明

---

## 一、项目背景与目标

### 1.1 项目背景

基于现有 mappAlarm 系统的局限性：
- 存储空间有限（仅几十 MB）
- 采用先进先出模式，早期数据会被覆盖
- 数据无法备份
- Hypervisor 系统损坏后数据无法找回

### 1.2 建设目标

构建一套基于数据库的历史报警系统，实现：
- ✅ 长时间数据记录与存储
- ✅ 灵活的查询功能（按时间、批号）
- ✅ 数据可备份、可迁移
- ✅ 与当前报警系统并存，互不影响

## 四、历史报警数据规范

### 4.1 数据字段定义

历史报警系统采用**配置化字段映射**方式，支持根据项目需求灵活调整。

| 配置字段名 | 数据库字段 | 数据类型 | 说明 | 来源 |
|-----------|-----------|---------|------|------|
| **ts** | alarm_time | DATETIME | 时间戳（报警发生时间） | PLC 提供的时间 |
| **code** | alarm_code | VARCHAR(50) | 报警号/报警码 | PLC 报警 ID |
| **user** | alarm_user | VARCHAR(100) | 报警时的操作员 | mappUserX |
| **msg** | alarm_message | TEXT | 报警详细描述 | PLC 报警文本 |
| **severity** | alarm_level | ENUM | 严重程度分级 | PLC 报警等级 |
| **state** | alarm_state | ENUM | 报警状态（激活/清除） | 报警生命周期状态 |
| **batch_number** | batch_number | VARCHAR(100) | 当前生产批次号 | MES/PLC |

### 4.2 数据结构定义

#### 4.2.1 字段映射关系

| 配置字段 | 数据库字段 | 数据类型 | 说明 |
|---------|-----------|---------|------|
| **ts** | alarm_time | DATETIME | 时间戳（PLC 提供的时间） |
| **code** | alarm_code | VARCHAR(50) | 报警号/报警码 |
| **user** | alarm_user | VARCHAR(100) | 报警时的用户 |
| **msg** | alarm_message | TEXT | 报警信息/详细描述 |
| **severity** | alarm_level | ENUM | 报警等级（Critical/Major/Minor/Info） |
| **state** | alarm_state | ENUM | 报警状态（Active/Cleared） |
| **batch_number** | batch_number | VARCHAR(100) | 生产批号 |

#### 4.2.2 数据表结构

```sql
CREATE TABLE alarm_history (
    -- 主键字段
    id INT AUTO_INCREMENT,
    ts DATETIME NOT NULL COMMENT '时间戳',
    batch_number VARCHAR(100) NOT NULL COMMENT '生产批号',
    
    -- 报警信息字段
    code VARCHAR(50) NOT NULL COMMENT '报警号',
    user VARCHAR(100) COMMENT '用户',
    msg TEXT COMMENT '报警信息',
    severity ENUM('Critical', 'Major', 'Minor', 'Info') NOT NULL COMMENT '报警等级',
    state ENUM('Active', 'Cleared') NOT NULL DEFAULT 'Active' COMMENT '报警状态',
    
    -- 系统字段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
    
    -- 主键约束：使用复合主键
    PRIMARY KEY (id, ts, batch_number),
    
    -- 索引优化
    INDEX idx_ts (ts),
    INDEX idx_batch_number (batch_number),
    INDEX idx_severity (severity),
    INDEX idx_state (state),
    INDEX idx_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='历史报警记录表';
```

#### 4.2.3 设计说明

**主键设计**：
- 采用复合主键 `(id, ts, batch_number)`
- `id`：自增 ID，确保唯一性
- `ts`：时间戳，支持时间范围查询
- `batch_number`：批号，支持按批次查询

**状态设计**：
- **Active**：报警激活状态（报警发生）
  - 当 PLC 报警触发时记录
  - 表示报警开始时间点
- **Cleared**：报警清除状态（报警消除）
  - 当 PLC 报警恢复时记录
  - 表示报警结束时间点
- **双触发机制**：每次状态变化都会产生一条独立的历史记录
  - 完整记录报警从发生到消除的全过程
  - 便于统计报警持续时间、分析报警频率

**配置化设计**：
- 表结构字段通过配置文件动态映射
- 支持根据项目需求调整字段名称和类型
- 配置文件建议采用 JSON 格式

![数据表结构示意](image/历史报警需求/数据表结构.png)

### 4.3 PLC 时间同步

- **时间源**：以 PLC 提供的系统时间为准
- **采集频率**：实时采集或定时同步
- **时间格式**：统一为 `YYYY-MM-DD HH:MM:SS`

## 五、功能需求

### 5.1 数据采集功能

#### 5.1.1 采集配置

- ✅ 支持灵活配置采集变量
- ✅ 可配置采集触发事件
- ✅ 可配置采集时间间隔
- ✅ 配置文件可采用 JSON 格式

#### 5.1.2 触发存储机制

系统采用**双触发**存储机制：

| 触发条件 | 说明 | 状态变化 |
|---------|------|----------|
| **报警激活** | PLC 报警触发时立即存储 | `state` = Active |
| **报警清除** | PLC 报警消除时立即存储 | `state` = Cleared |

**设计要点**：
- 每次状态变化都会产生一条新的历史记录
- 完整记录报警的生命周期（从激活到清除）
- 便于后续追溯和分析

#### 5.1.3 采集流程

```
PLC 报警状态变化 
  → OPC UA 读取报警数据 (code, msg, severity)
  → 获取 PLC 时间戳 (ts)
  → 关联当前用户信息 (user)
  → 获取生产批号 (batch_number)
  → 判断报警状态 (Active/Cleared)
  → 写入数据库
```

### 5.2 数据存储功能

#### 5.2.1 存储策略

- **触发存储**：报警状态变化时立即存储（激活/清除）
- **批量存储**：支持批量插入优化性能
- **断点续传**：网络中断恢复后自动补传
- **完整性保证**：确保每次状态变化都被记录

#### 5.2.2 存储示例

单次报警生命周期的存储记录示例：

| 记录 ID | ts (时间戳) | code (报警码) | state (状态) | batch_number (批号) | 说明 |
|--------|------------|--------------|-------------|-------------------|------|
| 001 | 2026-03-24 10:00:00 | ALM001 | Active | BATCH-2026-001 | 报警激活 |
| 002 | 2026-03-24 10:05:30 | ALM001 | Cleared | BATCH-2026-001 | 报警清除 |

#### 5.2.3 存储分区

- 可考虑按时间周期分表（如按月分表）
- 便于数据管理和查询优化

### 5.3 数据查询功能

#### 5.3.1 查询条件

| 查询维度 | 说明 | 示例 |
|---------|------|------|
| **时间范围查询** | 支持起始时间和结束时间 | 2026-03-01 至 2026-03-31 |
| **批号查询** | 根据生产批号精确查询 | Batch-2026-001 |
| **组合查询** | 时间 + 批号联合查询 | 某批次在某时间段的所有报警 |
| **报警等级筛选** | 按严重程度筛选 | 仅显示 Critical 级别 |
| **报警状态筛选** | 按确认状态筛选 | 仅显示未确认报警 |

#### 5.3.2 查询性能要求

- 支持并发查询（暂定 10 组并发请求）
- 跨表查询能力
- 大数据量查询响应时间 < 5 秒

### 5.4 数据显示功能

#### 5.4.1 mappView 界面展示

- 历史报警列表显示
- 支持分页浏览
- 支持排序（按时间、等级等）
- 支持导出功能

![历史报警查询界面](image/历史报警需求/查询界面原型.png)

#### 5.4.2 显示要素

- **Who**（用户）：报警时的操作员 → `user` 字段
- **When**（时间）：报警发生时间 → `ts` 字段
- **What**（报警信息）：
  - 报警码 → `code` 字段
  - 报警信息 → `msg` 字段
  - 报警等级 → `severity` 字段
- **Status**（状态）：报警状态 → `state` 字段 (Active/Cleared)
- **Batch**（批号）：生产批号 → `batch_number` 字段

### 5.5 数据管理功能

#### 5.5.1 数据备份

- 支持定期自动备份
- 支持手动备份
- 备份文件格式化

#### 5.5.2 数据迁移

- 支持数据导出到其他数据库
- 支持历史数据归档

#### 5.5.3 数据恢复

- 支持从备份文件还原数据
- 防止误删除后的数据恢复
