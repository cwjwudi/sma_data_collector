# 如何修复「未加忽略文件的错误推送」

**文档用途：** 记录在有人误将未配置 `.gitignore` 的程序（含错误路径、Temp、用户文件等）推送到仓库后，如何从历史中彻底修复。

**适用场景：**

- 合作者推送时未添加/未生效忽略文件，导致 Temp、Diagnosis、`*.set`、`*.isopen` 等被提交
- 使用了错误的项目路径（如根目录下的工程文件夹，而非约定的 `_Prj/xxx`）
- 希望从历史中**完全删除**这些错误提交与内容，并用正确路径和忽略规则、以维护者身份重新提交

---

## 一、修复目标

1. **历史中不再包含**错误提交者的相关 commit
2. **历史中从未出现**错误路径（如根目录 `SD_SMA_SCADA_DEMO`），只保留正确路径（如 `_Prj/SD_SMA_SCADA_DEMO`）
3. **Temp/用户文件等**从未进入版本库
4. 由**维护者本人**以正确作者信息做一次「正确路径 + 正确 .gitignore」的提交并推送
5. 合作者按说明同步后，本地与远端一致

---

## 二、前置准备

- 确认当前仓库的 `user.name` / `user.email`（将作为新提交的作者）  
  `git config user.name` / `git config user.email`
- 确认「错误提交」的**前一个**正常提交的 hash（记为 `<BASE>`），后续所有操作从该点开始重做
- 若有本地未提交修改，先 `git stash` 备份

---

## 三、操作步骤（概要）

### 1. 基于「错误提交之前」建分支

```bash
git fetch origin
git checkout -b fix-push <BASE>
```

例如：`<BASE>` = `a4002d8`（错误推送前的最后一个正常提交）。

### 2. 只引入「正确路径」和「正确 .gitignore」

从**已经正确的**某个提交（例如之前重写后只含 `_Prj` 和根目录 `.gitignore` 的提交）中，只检出需要的路径，不要带入错误路径：

```bash
git checkout <CORRECT_TREE> -- .gitignore _Prj
```

- `<CORRECT_TREE>`：某次只包含 `_Prj/项目名` 和根目录 `.gitignore` 的 commit
- 这样历史里**从未**出现根目录下的错误工程文件夹

### 3. 以维护者身份提交

```bash
git commit --author="你的名字 <你的邮箱>" -m "程序 demo 初版（_Prj/项目名）"
```

提交后，该 commit 仅包含正确路径和忽略规则，且作者为维护者。

### 4. 接上自己的后续提交（若有）

若在修复过程中还有自己的文档等修改，可：

```bash
git cherry-pick <你的文档提交hash>
```

### 5. 用新历史覆盖 main 并推送

```bash
git checkout main
git reset --hard fix-push
git branch -d fix-push
git push --force-with-lease origin main
```

- `--force-with-lease` 比 `--force` 更安全，避免覆盖他人新推送

### 6. 删除本地遗留的错误路径文件夹（若存在）

历史重写后，Git 不会自动删除「曾经被跟踪、现在不再跟踪」的目录在磁盘上的残留。若根目录下仍存在错误路径的文件夹（如 `SD_SMA_SCADA_DEMO`），可手动删除，避免与 `_Prj/` 下正确路径混淆：

- **Windows PowerShell：**  
  `Remove-Item -Recurse -Force "SD_SMA_SCADA_DEMO"`  
  （在仓库根目录执行，且仅删除根目录下的该文件夹，不要删 `_Prj/SD_SMA_SCADA_DEMO`）

- 或直接在资源管理器中删除该文件夹。

---

## 四、合作者需要做的

历史被重写后，合作者必须用远端覆盖本地，否则会一直看到旧历史或冲突：

```bash
git fetch origin
git reset --hard origin/main
```

若有未推送的本地提交，请先自行备份（如建分支或复制仓库）再执行上述命令。

---

## 五、本仓库实际执行过的修复（参考）

- **问题：** 合作者将程序以根目录 `SD_SMA_SCADA_DEMO` 推送，且未加忽略，Temp/Diagnosis/`*.set`/`*.isopen` 等一并入库；后又有一笔「初版demo更新路径」将工程迁到 `_Prj/SD_SMA_SCADA_DEMO`。
- **处理：**  
  - 从错误提交之前的 commit 建分支，仅从「正确树」中 checkout `.gitignore` 与 `_Prj`，做一笔以维护者（Haochen Qi）为作者的提交。  
  - 再 cherry-pick 维护者的文档更新提交。  
  - 将 `main` 重置到该新历史并 `git push --force-with-lease origin main`。  
  - 删除本地根目录下遗留的 `SD_SMA_SCADA_DEMO` 文件夹。
- **结果：** 历史中不再包含合作者的提交与错误路径；仅存在 `_Prj/SD_SMA_SCADA_DEMO` 及正确忽略规则。

---

## 六、根目录与工程内 .gitignore 建议（Automation Studio）

- **仓库根目录 `.gitignore`** 建议至少包含：  
  `Temp/`、`Diagnosis/`、`*.set`、`*.isopen`、`*.brk`、`*.tch`、`*.tr`，以及文档/编辑器相关（如 `.obsidian`、`.trash`）。
- **`_Prj/项目名/.gitignore`** 可沿用 Automation Studio 常用规则：  
  `Temp/`、`Binaries/`、`Diagnosis/**`（及需要的例外）、`*.set`、`*.isopen`、`Upgrades/` 等，避免再次误提交临时与用户文件。

以上可作为「错误推送未加忽略文件」后的标准修复流程，供后续同类问题参考。
