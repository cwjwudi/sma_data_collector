## 1. 引言

### 1.1 编写目的

本文档描述新马药机 SCADA 系统 - 历史报警子系统的软件架构设计，为开发团队提供技术指导和实现依据。

### 1.2 背景

基于现有 mappAlarm 系统的局限性（存储空间有限、数据无法备份等），需要开发一套独立的基于数据库的历史报警系统。

### 1.3 范围

本架构设计涵盖：
- 后端数据采集与存储服务
- 前端 mappView 显示界面
- 数据库设计与存储方案
- OPC UA 通讯接口
- HTTP API 接口

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| SCADA | 监控与数据采集系统 (Supervisory Control and Data Acquisition) |
| OPC UA | 开放平台通信统一架构 (Open Platform Communications Unified Architecture) |
| PLC | 可编程逻辑控制器 (Programmable Logic Controller) |
| HMI | 人机界面 (Human Machine Interface) |
| API | 应用程序接口 (Application Programming Interface) |
| ORM | 对象关系映射 (Object-Relational Mapping) |

## 2. 系统概述

### 2.1 系统目标

构建一套基于数据库的历史报警系统，实现：
- ✅ 长时间数据记录与存储

### 4.2 架构分层说明

#### 4.2.1 用户层
- **mappView**: B&R HMI 界面，运行在 Arsim 环境
- **Web 浏览器**: 通过 HTTP API 访问数据
- **移动终端**: 未来扩展支持

#### 4.2.2 应用服务层
- **数据采集服务**: 从 PLC 采集报警数据
- **数据查询服务**: 提供 RESTful API 查询接口
- **数据管理服务**: 备份、恢复、导出等管理功能

#### 4.2.3 数据访问层
- **OPC UA Client**: 连接 PLC 读取实时数据
- **SQLAlchemy ORM**: 数据库访问抽象层

#### 4.2.4 数据存储层
- **PLC 设备**: 报警数据源
- **MySQL/MariaDB**: 历史数据存储

### 5.2 核心技术选型

| 层次 | 技术组件 | 选型 | 理由 |
|------|---------|------|------|

| **配置管理** | 配置文件 | JSON + YAML | 易读易写、解析简单 |
| **日志系统** | 日志框架 | logging (内置) | 标准库、无需额外依赖 |
| **前端 HMI** | HMI 框架 | mappView | B&R 官方支持、与 Arsim 集成 |
| **图表库** | 可视化 | ECharts | 开源免费、功能丰富 |
| **PDF 阅读** | PDF 渲染 | PDF.js | Mozilla 开源、浏览器兼容 |

## 6. 数据架构

### 6.1 数据库设计

#### 6.1.1 核心表结构

**alarm_history (历史报警表)**

```sql
CREATE TABLE alarm_history (
    -- 主键字段
    id INT AUTO_INCREMENT,
    ts DATETIME NOT NULL COMMENT '时间戳',
    batch_number VARCHAR(100) NOT NULL COMMENT '生产批号',
    
    -- 报警信息字段
    code VARCHAR(50) NOT NULL COMMENT '报警号',
    user VARCHAR(100) COMMENT '用户',
    msg TEXT COMMENT '报警信息',
    severity ENUM('Critical', 'Major', 'Minor', 'Info') NOT NULL COMMENT '报警等级',
    state ENUM('Active', 'Cleared') NOT NULL DEFAULT 'Active' COMMENT '报警状态',
    
    -- 系统字段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
    
    -- 主键约束：使用复合主键
    PRIMARY KEY (id, ts, batch_number),
    
    -- 索引优化
    INDEX idx_ts (ts),
    INDEX idx_batch_number (batch_number),
    INDEX idx_severity (severity),
    INDEX idx_state (state),
    INDEX idx_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='历史报警记录表';
```

#### 6.1.2 分表策略

采用**按时间周期分表**策略：

```
alarm_history_202603  -- 2026 年 3 月数据
alarm_history_202604  -- 2026 年 4 月数据
alarm_history_202605  -- 2026 年 5 月数据
...
```

**优点**：
- 避免单表过大
- 便于数据归档
- 提高查询性能
- 简化数据清理

### 6.3 数据字典

class AlarmDataStorage:

## 10. 安全架构

### 10.1 安全策略

#### 10.1.1 数据安全

- **访问控制**: 基于角色的权限管理
- **数据加密**: 敏感数据加密存储
- **审计追踪**: 所有操作记录日志
- **防篡改**: 数据校验和验证

#### 10.1.2 网络安全

- **端口限制**: 仅开放必要端口
- **防火墙**: 配置访问规则
- **认证机制**: API Token 验证
- **速率限制**: 防止恶意请求

## 11. 质量属性

### 11.1 性能指标

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| **采集延迟** | < 1 秒 | 从 PLC 触发到入库时间 |
| **查询响应** | < 5 秒 | 百万级数据量下 |
| **并发用户** | ≥ 10 个 | 同时在线查询 |
| **系统可用性** | 99.9% | 7×24 小时运行 |

### 11.2 可靠性指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **数据完整性** | 100% | 不丢失任何报警记录 |
| **故障恢复** | < 5 分钟 | 系统异常自动恢复 |
| **MTBF** | > 1000 小时 | 平均无故障时间 |

### 11.3 可维护性

- **日志完整**: 记录所有关键操作
