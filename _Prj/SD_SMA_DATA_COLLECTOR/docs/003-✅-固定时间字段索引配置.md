# ✅ 固定时间字段索引配置

## 目标

索引配置除当前数据组的 OPC UA 点位外，还可选择数据表固定字段 `collection_time` 和 `created_at`，并支持与业务点位组成复合索引。

## 实现

- 统一声明固定索引字段：`collection_time`、`created_at`。
- 运行配置加载校验允许“当前组数据点 + 固定索引字段”，其他字段继续拒绝。
- Web 配置保存校验采用相同规则。
- 索引配置弹窗将两个固定字段标注为“固定采集时间”和“固定创建时间”。
- 弹窗中的业务点位只显示当前数据组 `data_points`，不再显示保存时会被后端拒绝的其他组点位。
- 数据库执行层无需改变，继续支持普通索引、唯一索引和多列复合索引。

配置示例：

```json
"indexes": [
  {
    "name": "idx_product_collection_time",
    "columns": ["collection_time"],
    "unique": false,
    "index_type": "btree"
  },
  {
    "name": "idx_product_code_created",
    "columns": ["ProductCode", "created_at"],
    "unique": false,
    "index_type": "btree"
  }
]
```

## 验证

- 专项测试：`19 passed`。
- 完整采集器回归：`165 passed, 4 warnings`；4 条均为既有弃用或测试返回值警告。
- SQLite 验证：成功创建 `collection_time` 单列索引和 `SensorValue, created_at` 复合索引，列顺序正确。
- 测试 MySQL 验证：
  - `idx_codex_collection_time` → `collection_time`；
  - `idx_codex_sensor_created` → `SensorValue, created_at`；
  - 验证后临时表已删除，读回残留数为 `0`。
