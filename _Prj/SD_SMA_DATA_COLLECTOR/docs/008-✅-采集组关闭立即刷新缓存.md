# ✅ 已完成：采集组关闭立即刷新缓存

## 目标

配置了外部启停点位的采集组从 `1/True` 切换为 `0/False` 时，不等待达到 `batch_insert_size`，立即将该组已经进入批量缓存的数据写入数据库。

## 实现

- 外部信号关闭时，先取消并等待该组采集任务完全停止。
- 采集器发出组停用通知，运行时将其转换为存储处理器的按组刷新请求。
- 刷新请求由现有存储循环串行处理，避免与正常批量写入并发修改队列。
- 只强制写入被关闭组的缓存，其他组仍按各自批量阈值处理。
- 数据库写入失败时保留刷新请求及原数据，继续使用现有持久化 outbox 或内存重试流程。
- 系统正常停止时清理尚未消费的刷新请求，并继续使用原有停机全量刷新。

## 验证

- 专项及完整自动化回归：`204 passed, 4 warnings`。
- 真实 PLC/MySQL 冒烟测试：关闭时 7 行未满批缓存全部提交，刷新耗时 0.062 秒，停用期间零采集且恢复成功。
- 一小时真实 PLC/MySQL 稳定性测试：运行 3608.188 秒，30 个关闭窗口全部通过。
- 30 次关闭共立即刷新 3072 行；单次刷新延迟最小 0.078 秒、平均 0.532 秒、最大 1.047 秒。
- 测试期间采集 3179 行，SQLite outbox 接收及完成均为 3179 行；数据库写入失败、唯一键冲突、死信和停机残留均为 0。
- 所有停用窗口均为零误采，所有重新启用均恢复成功，控制点读取失败和无效值均为 0。
