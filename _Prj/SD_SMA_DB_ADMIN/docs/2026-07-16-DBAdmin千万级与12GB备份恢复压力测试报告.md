# SD SMA DB Admin 千万级与 12GB 备份恢复压力测试报告

## 结论

本轮完成 3 轮两张千万级表的完整备份/恢复，并完成 1 轮 12.32GB SQL 文件容量备份/恢复。四轮的行数、主键范围和代表性业务字段 CRC 摘要全部一致，`mismatches=[]`。

SD SMA DB Admin 已能处理此规模的逻辑备份、服务器端直接恢复和 HTTP Range 断点下载。在当前 NAS MariaDB 环境下，12.32GB 容量轮备份约 16.7 分钟，校验加恢复约 47.8 分钟。

## 环境

- 数据库：MariaDB 10.11.11，InnoDB，服务地址已脱敏不写入报告。
- 客户端：MariaDB 10.11.11 Windows x64；官方 ZIP SHA-256 校验通过（`4022b09a...b4ddbf`）。
- 服务端参数：`max_allowed_packet=1MB`，`innodb_buffer_pool_size=16MB`。
- 本地测试起始可用空间约 346GB，完成后约 324GB。

## 已实施的修改

- `.partial` 写入、失败清理、成功原子改名和唯一文件名。
- 备份前磁盘空间预检，备份后 SHA-256 manifest。
- HTTP Range 断点下载及页面下载入口。
- 服务器已完成备份直接恢复，避免 12GB 文件再次上传。
- 恢复前强制 manifest 大小与 SHA-256 校验。
- Origin 校验、120 秒操作绑定一次性确认令牌、DOM XSS 安全渲染、配置密码不回传。
- 任务并发上限、日志上限、CLI 超时和长任务取消。
- CSV 清表导入从 `TRUNCATE + autocommit` 改为可回滚的 `DELETE + INSERT + commit`。

## 回归与局限

- 快速自动化回归：26 项通过；覆盖跨站拒绝、一次性令牌、密码脱敏、Range、原子备份、残片清理、manifest、恢复哈希拒绝、并发上限和取消。
- 下载断点能力依赖客户端使用 Range；普通浏览器下载是否自动续传由浏览器决定。
- `--single-transaction` 的一致性保证主要适用于 InnoDB；非事务引擎需另行停写或加锁策略。
- 服务端 Buffer Pool 仅 16MB，大库恢复耗时明显；生产窗口应预留至少 1 小时，并先评估 NAS 磁盘与 MariaDB 参数。
- 本轮未测非 InnoDB 表、有效 TLS 远程连接和服务进程强制崩溃后的持久任务恢复。
