# 模版 / 版式异步加载问题与修复

> **状态：** 已修复（2026-05）  
> **关联提交：** `aba82d9` — `fix(SD_SMA_ReportEditor): 快速入门体验与模版版式加载可靠性`  
> **涉及页面：** 模版管理、版式与页眉页脚、版式编辑器、模版编辑器

---

## 现象（用户侧）

在 **macOS / Windows** 桌面版或开发环境中：

1. 打开 **模版管理** 或 **版式与页眉页脚** 时，列表或缩略图加载**明显偏慢**（模版数量多时更明显）。
2. 在数据**尚未加载完成**时切换到其他侧边栏页面，再切回来时：
   - 模版缩略图区域长期停留在「加载…」，或整页**看似空白**；
   - 版式列表可能被误判为「暂无版式」；
   - 偶发被**意外跳转**到其他路由（例如从版式页被带回模版列表）。

---

## 根因分析

### 1. 异步加载无「过期保护」

模版 / 版式页在 `onMounted` 或路由切换时发起 `fetch` 拉取数据，但**未在组件卸载时作废进行中的请求**。

用户在加载中途离开页面后，旧请求仍可能在返回时：

- 向已卸载或已切换的组件 **写回 `ref` 状态**；
- 在模版编辑器 `boot()` 失败分支中调用 **`router.replace`**，干扰当前所在页面。

### 2. 模版缩略图逐条串行加载

`TemplateManager.vue` 的 `hydrateThumbs()` 对每条模版摘要 **顺序** 调用 `GET /templates/{id}`，模版多时总耗时长。

加载慢时用户更容易中途切页；与问题 1 叠加后，部分卡片长期无法恢复显示。

### 3. 失败状态处理不当

| 位置 | 原行为 | 后果 |
|------|--------|------|
| 模版缩略图 | 单条失败时 `cache[id] = null` | 同一页面内缺少明确失败态与重试入口，用户只能刷新或切页碰运气 |
| 版式列表 | `reload()` 无 `loading` 标志 | 请求进行中时 `presets` 仍为空数组，界面显示「当前还没有任何版式」，**像整页空白** |
| 版式 / 模版编辑器 | 加载失败或慢请求与新一轮加载竞态 | 旧结果覆盖新页面，或 `working` / `editing` 长期为 `null` |

---

## 修复方案

### 公共机制：`useStaleGuard`

新增 `frontend/src/composables/useStaleGuard.ts`：

- 组件 **`onBeforeUnmount` 时递增 generation**；
- 异步任务开始时记录 `token`，写回状态前检查 **`isStale(token)`**，过期则丢弃结果；
- 提供 **`mapPool()`**，用于有限并发（模版缩略图默认 **4 路并行**）。

### 模版管理（`TemplateManager.vue`）

- 摘要列表 `load()` 与缩略图 `hydrateThumbs()` 均带过期保护；
- 缩略图改为并发拉取，不再逐条串行；
- 新增 `thumbLoading` / `thumbFailed` 集合：失败显示 **「预览加载失败」+ 重试**，不再写 `null` 占坑；
- `loadPresets()` 同样检查 stale，避免卸载后写版式缓存。

### 版式列表（`LayoutPresets.vue`）

- `reload()` 增加 **`loading`** 状态，加载中显示「正在加载版式，请稍候…」；
- 仅在 **非 loading 且列表为空** 时显示「暂无版式」；
- 加载失败写入 **`msg`** 提示，而非静默留空。

### 版式编辑器（`LayoutPresetEditor.vue`）

- `loadWorking()` 开始时清空 `working`，避免短暂展示上一份版式；
- 全程 stale 检查；路由 `params.id` 变化时已有 `watch` 重新加载。

### 模版编辑器（`TemplateEditorWorkspace.vue`）

- `boot()` 增加 stale 保护；
- **移除**加载失败时强制 `router.replace` 到模版列表的行为（改为页内「载入中…」/错误提示）；
- **`watch(route.params.id)`** 切换模版 id 时重新 `boot()`。

## 验证建议

1. **模版管理 · 缩略图**：模版 ≥5 条时进入页面，加载未完成时切到「数据源配置」再返回 → 缩略图应继续加载或已全部显示；失败项可点 **重试**。
2. **版式列表**：慢网络或后端冷启动时进入 → 应先见「正在加载版式…」，不应先闪「暂无版式」。
3. **加载中切页**：版式编辑 / 模版编辑打开后立刻切走再回来 → 应重新加载，不应空白或跳错页。
4. **并发**：模版多时缩略图完成时间应明显短于修复前（串行 N 次请求）。

## 后续可选优化（未做）

- 后端提供 **批量获取模版摘要+缩略图所需字段** 的接口，减少 N+1 请求；
- 模版 / 版式列表 **内存缓存 + TTL**，返回页面时先展示缓存再后台刷新；
- `fetch` 层统一 **AbortController**，与 `useStaleGuard` 联动取消 HTTP 请求（当前仅在 UI 层丢弃过期写回）。
