## 目标

在 **同机 + mappView 必须可操作 + 完全不闪** 硬约束下，立项并完成 **旁路 Electron `printToPDF`** 的引擎选型与 Spike，给出可实施的技术路线（032 **P2-B** / 030 **Z2**）。

本版**不以调参/绑核宣称达标**；本版结束时应能回答：「用哪条引擎路径进实现版」。

## 背景（已锁定，不重议）

| 约束 | 决定 |
|------|------|
| 分机 | 近期不做 |
| mappView | 零闪；掉线重载 ~10s 不可接受 |
| 结批中 HMI | **必须能操作** → 否决导出互斥窗 |
| AR+Windows Hypervisor | mappView/Chromium **不可设 CPU 相关性** |
| 现状 | 唯一出 PDF 路径 = 隐藏 `BrowserWindow` + `webContents.printToPDF`（第二套 Chromium） |

现状尖峰源（保留取数/分卷/写盘，只换「渲染→字节」）：

```text
PdfExportView DOM + @page CSS → notifyPdfExportReady → main.printToPDF → writeFile
```

关键调用：`frontend/electron/main.cjs`（`printToPDF`）；`PdfExportView.vue`（ready）；分卷/fill-cache 可保留。

## 候选引擎

| ID | 方案 | 是否第二 Chromium | 版式保真 | 工控机风险 | 工程量 | 倾向 |
|----|------|-------------------|----------|------------|--------|------|
| **A** | 导出卡片模型 → **pdf-lib / PDFKit** 矢量绘制 | 否 | 需重做表格/分页绘制；与 DOM 1:1 难 | **最低**（无浏览器合成） | 高 | **主推 Spike** |
| **B** | 每页序列化 HTML/CSS → **WeasyPrint**（或同类非 Chromium）子进程 | 否 | 中高（CSS 子集） | 低–中（Python/二进制依赖） | 中高 | **备选 Spike** |
| **C** | 每页栅格（canvas/skia）拼 PDF | 否 | 中（图像 PDF，体积大） | 中（仍吃 CPU，可能卡） | 中 | 慎重 |
| **D** | Playwright / 另一 Chromium `printToPDF` | **是** | 高 | **高**（与 mappView 同构争用） | 低 | **否决** |
| **E** | 仅 Idle + 绑 1 核 + 超长 yield（仍 printToPDF） | 是 | 高 | 不保证零闪 | 低 | **否决作达标路径** |
