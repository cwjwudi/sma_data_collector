# 版本 Plan

本目录用于记录 **Report Editor（AI 版）每个版本** 的**产品计划**（目标、范围、验收、不做项、版本级规则）。

> 仓库级任务推进规则见根目录 [CLAUDE.md](../../../../CLAUDE.md) / [AGENTS.md](../../../../AGENTS.md)。  
> **本目录不是任务看板**：子任务状态（✅/🚧/⌛️）写在根目录 `docs/NNN-状态-主题.md`；本目录只按版本号沉淀计划正文。

## 文档分工

| 文档 | 用途 |
|------|------|
| **本目录 `0.x.y.md`** | 发版前 / 开发中的**版本计划**（要做什么、验收、版本规则） |
| [`../007_版本发布记录.md`](../007_版本发布记录.md) | 发版后的**事实记录**（已做成什么） |
| 根目录 [`docs/NNN-状态-主题.md`](../../../../docs/) | **任务看板**（H1 子任务状态与证据） |
| 根目录 [`todo.md`](../../../../todo.md) | 按日期**倒序**的精炼索引 |

## 文件命名

每个版本一个文件，**文件名 = 版本号**（与 `frontend/package.json` 的 `version` 一致）：

```text
0.3.57.md
0.3.58.md
1.0.0.md
```

不要加 `v` 前缀、不要夹空格。

## 建议结构

```markdown
# 0.x.y Plan

- **状态**：草稿 / 进行中 / 已发版
- **任务看板**：链接到 `docs/NNN-状态-主题.md`（若本版有实施任务）
- **对应发布记录**：见 `007_版本发布记录.md`（发版后补）

## 目标
## 范围（可用 [ ] 勾选，执行后与看板 H1 对齐更新）
## 不做
## 验收
## 规则（可选，本版沉淀的工程约定）
## 备注
```

## 与 CLAUDE 流程的关系

1. **写计划**：在本目录新建/更新 `0.x.y.md`。
2. **开工实施**：在 `docs/` 建或复用 `NNN-🚧-主题.md`，子任务用 H1（✅/🚧/⌛️）；本 Plan 顶部链到该看板。
3. **收尾**：看板 H1 标状态；`todo.md` 顶部追加日期索引；发版事实写入 `007_版本发布记录.md`；再按队列规则 `commit`+`push`。
