> 2026-07-12 对 `_Prj/SD_SMA_ReportEditor/frontend/` 表格控件系统做的三路并行深度审计（几何度量层 / SQL 填充分页链路 / 组件层与重复），及据此规划的修复执行列表。

## 系统范围

- **组件层**：`components/report-template/` — TemplateBodyCanvas.vue(2297)、TemplateElementProps.vue(1530)、LayoutPresetPaperCanvas.vue(1716)、ZoneTableStatic.vue(167)、TableColumnResizeGutters.vue(130)、TemplateTableSqlFillFields.vue(504)、TemplateTableSqlVisualPanel.vue(1650)

## 评级与总结

设计 B+ / 实现 B- / 完整度 C+。架构主干合理（预览=导出复用同一套 Vue 组件、异步竞态用 generation 兜住、底层度量数学正确），但存在三层系统性问题：(1) 预览取 1000 行/导出取全量造成分页份数「所见非所得」；(2) 表格模型复制成 Template 系与 Zone 系两套且已漂移；(3) 一批整类能力缺失（合并单元格、中间列增删、请求取消、跨份数据快照）。无致命崩溃 bug，但有多个导致数据错误或「打印与屏幕不一致」的正确性 bug。

# ✅ 已完成：P2-B 窄/多列表格列宽拖拽失效

- **问题（CONFIRMED 推导）**：`table-cell-metrics.ts:341` `applyTableColumnResizeDeltaPx` 在内侧宽 < 列数×26 时钳制值符号反转，末行 `Math.max(lo, round(w))` 把所有列强抬 26 破坏总宽守恒。净效果：30 列表格在窄于 788px 的正文/页眉里列宽拖拽静默失效。两画布共用同一函数同时中招。
- **修复**：可收缩量 `maxLeft/maxRight` 限为非负（`Math.max(0, widths[x]-lo)`）避免方向反转；各列均 ≤ 下限的退化区两侧可收缩量均为 0 → 返回 null（拖拽无从满足，而非产出垃圾）；末行改为只四舍五入，不对全列强制下限（触碰的两列已保证 ≥ 下限，未触碰列保持原值，守恒不破坏）。
- **验收**：`report-template.test.ts` 新增 3 用例（退化区返回 null / 守恒且只动相邻两列且方向不反转 / 过量拖拽钳制到下限），先红后绿；前端全套 233 passed。提交 d82bd57。
