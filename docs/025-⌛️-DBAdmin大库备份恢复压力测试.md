# ⌛️ 未完成：至少三轮完整备份恢复压力测试

每轮都执行“备份 → SHA-256 校验 → Range 下载/中断续传 → 恢复到新测试库 → 结构与数据一致性校验”。

1. 第 1 轮：单表至少 10,000,000 行，建立基准耗时和吞吐。
2. 第 2 轮：多表场景，至少两张千万级表，包含索引、视图、触发器/事件（若参考结构具备）。
3. 第 3 轮：约 12GB 备份文件的容量场景，验证长时任务、下载续传和恢复。
4. 额外故障轮：可控模拟子进程失败、下载中断、连接超时和取消，不对参考库注入故障。

每轮记录：行数、数据/索引大小、备份文件大小、备份/恢复耗时、MB/s、SHA-256、CPU/内存/磁盘峰值、MySQL 错误和业务影响。

一致性判定至少包含：

- 数据库对象清单与标准化 `SHOW CREATE TABLE` 对比。
- 每表精确 `COUNT(*)`、主键 `MIN/MAX`、NULL 分布和关键数值聚合。
- 按主键分块计算的确定性摘要，并进行固定随机种子抽样逐行对比。
- 备份文件和完整下载文件的 SHA-256 完全一致。

通过标准：至少 3 轮千万级完整循环全部成功，结构、行数、分块摘要和文件哈希无差异，且无未标记残片、无非测试库写入。
